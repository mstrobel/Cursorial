# Cross-subsystem contract-coherence punch list

## A. Render architecture: scene granularity, compositor, opacity (the biggest fault line)

**1. Three incompatible scene-granularity models — S1 vs S4 vs S8.** S1 §3.7 builds the entire render integration on **zones**: one `Scene` per *render boundary*, with six promotion predicates (window root, `Opacity<1`, `RenderOffset≠0`, `ClipToBounds`, `ScrollContentPresenter`, `IsRenderBoundary`), sticky promotion, a per-window `RenderTree` producing a *multi-layer* flat list via `CollectLayers`. S4 §3.2/§3.7/§7 builds on **exactly one scene per top-level surface** ("one layer per surface for its whole lifetime"; "per-window scene stacks — deferred; v1 implements exactly 1"), with `ISurfaceRasterizer` rastering the whole tree into that single scene. S8 §3.5 claims a **third** model "pinned with S1": one scene per window plus `IElementLayer` sub-scenes for exactly {scroll viewports (banded), ProgressBar indeterminate, S4 popups}, via a `UIElement.RequestLayer(LayerOptions)` API that appears in no other spec. S8's claim of a pin is unilateral — S1 contains no `IElementLayer`, no `RequestLayer`, no banding. **Resolution:** pick S1's zone engine as the implementation (it is the only model that delivers invariant 3 for scroll/opacity/slide *and* already has hit-test/composite-order proofs), then reconcile the other two against it: (a) S4's `TopLevelSurface` wraps an S1 `RenderTree` and `Surfaces`/`CompositeFrame` consume `CollectLayers` output (S4's "exactly 1 layer per window" and `ISurfaceRasterizer` whole-surface raster are deleted; its layer-count-stability analysis re-done over boundary counts); (b) S8's `IElementLayer`/`RequestLayer` is re-expressed as S1 boundary promotion (`IsRenderBoundary` + a new banded option on `ScrollContentPresenter`), and S8's "one scene per window" prose is corrected to "one scene per zone, where the default window has few zones". Also resolve the stickiness clash: S8's ProgressBar layer "exists only while `:indeterminate`" violates S1's sticky-promotion/layer-count-stability rule — either the layer persists once minted (S1 rule) or S1 adds the demotion escape valve it deferred.

**2. `ScrollContentPresenter` is specified twice with contradictory designs — S1 §2.4/§3.9 vs S8 §2.4/§3.9.** Base class (`UIElement` with `Content` vs `sealed : ContentPresenter`); scene policy (extent-sized scene + `SceneBudgetCells = 262,144` + degraded viewport-mode fallback with stroke/formatted-text drop, vs banded scene `[anchor, anchor+viewport+2K)` + re-anchor, `LayoutLimits.MaxScrollExtent = 32,000`); offsets (S1: styled properties `[AffectsComposite]`, arrange-time re-coercion — therefore storyboard-animatable; S8: `DirectProperty` on ScrollViewer, hand-routed, "NOT storyboard-animatable"). **Resolution:** one owner — S1 keeps the type; graft S8's banded policy into S1's SCP as *the* scene policy (it strictly dominates S1's degraded fallback: bounded memory, no straddle-drop artifacts), keep S1's styled `ScrollOffset*` (`AffectsComposite` + re-anchor check in the metadata handler), which also deletes S8's "no smooth scroll in v1" caveat; ScrollViewer's `DirectProperty` offsets become two-way mirrors of SCP's styled offsets. Reconcile the two extent caps into one named constant.

**3. Element `Opacity`: S1/S5 vs S4.** S1 declares `UIElement.Opacity` (`AffectsComposite`, boundary-promoting, opacity groups multiply); S5's toast example animates `UIElement.OpacityProperty`; S4 §2.1 declares `Window.OpacityProperty` and states "Window-only in v1: UIElement has no element opacity (deferred to scene nesting)". **Resolution:** S1 wins (element opacity via boundary promotion is load-bearing for S5's fade lane and S8's theming); S4's `Window.Opacity` becomes an `AddOwner` of the element registration, and its "no element opacity" sentence is deleted.

**4. `SceneCompositor` / `ScenePool` / screen-buffer ownership triangle — S1 vs S4 vs S6.** S1 §4 REQUIRES "S6 owns the screen `CellBuffer`, the single `SceneCompositor`, the shared `ScenePool`, the `FrameRenderer`" and pins renegotiate/resize transactions on S6 constructing fresh compositors. S4 §2.4/§8-Q2 pins "the WM owns the `SceneCompositor`" (recreating it on resize/`DesktopBackground` change only). S6 §1 owns buffer+renderer and delegates compositing to `IRenderSystem` (the merged S4/S1 object). Additionally: S6's `RenegotiateAsync` rebuilds `FrameRenderer` **and `CellBuffer`** but never recreates the compositor and never calls S4's `InvalidateAllSurfaces` or S1's per-window `Capabilities` re-stamp + `InvalidateAll` — a fresh target buffer under a stateful retained-target compositor is exactly the desync S1's transaction exists to prevent. **Resolution:** pin compositor + `ScenePool` ownership on the window/render system (S4's recommendation), confirmed in S6; amend S6 §3.5's renegotiate sequence to include "fresh `SceneCompositor`, `InvalidateAllSurfaces`/per-window `InvalidateAll`, `RenderTree.Capabilities` re-stamp" and the resize sequence likewise; delete S1's "S6 owns the compositor" line.

**5. Two hit-test implementations; z-order fidelity broken in S3's.** S1 §3.10 provides `RenderTree.HitTest` that *provably mirrors composite order* (boundary-layer list topmost-first, cached clips, ZIndex-sorted `CachedZOrder`), and explicitly says S-input's per-Move check "is simply a HitTest re-run". S3 §3.4 implements its own `Descend` over `VisualChildren` in reverse *collection* order using a `UIElement.LayoutBounds` (signed, window coords, composite-inclusive) that **S1 explicitly does not provide** (S1 removed all per-element absolute-bounds caches). S3's descent ignores `ZIndex` ordering and the zone-base rule, so its hit order diverges from paint order. **Resolution:** S3's dispatcher does the surface-level scan only and delegates intra-surface hit testing to `RenderTree.HitTest(surfaceLocal)`; `LayoutBounds` is dropped from S3's REQUIRES, replaced by `TranslateToWindow/ToLocal` (for `GetPosition`) and the `HitTest` seam. S1 owns hit-test z-order, full stop.

**6. `ClipsToBounds` panel-default contract would explode the layer count.** S3 §4 names "`bool ClipsToBounds` with **true as the panel default**" as a perf contract from the tree. S1 has `ClipToBounds` (name drift), default **false**, and `ClipToBounds == true` is a **boundary-promotion predicate** — honoring S3's default would mint a Scene per panel, the compositor's worst case. **Resolution:** delete S3's panel-default requirement (it becomes moot once item 5 routes hit testing through `RenderTree.HitTest`, which prunes via boundary clips); unify the property name to `ClipToBounds`.

**7. Element render signature: S8's `IElementRenderHost` vs S1's `RenderContext`.** S8 sketches `Render(DrawingContext ctx, Rect bounds)` with "bounds in ABSOLUTE scene coordinates"; S1's pinned virtual is `Render(RenderContext)` in element-local coordinates with the context performing translation (including for formatted text/strokes/shadows, which the Drawing push stack misses). **Resolution:** S1's `RenderContext` wins; S8's `IElementRenderHost` sketch is rewritten to cite it; S8's TextBlock `DrawFormattedText` note ("absolute scene coordinates") is restated as "RenderContext translates — draw element-local".

## B. Frame loop ordering and missing loop obligations (S6 vs everyone)

**8. S5's scheduler protocol vs S6's `IAnimationFrameDriver` don't line up.** S5 mandates `AnimationScheduler.Install` + `BeginFrame()` **before the input drain** (clock frozen so `BeginAnimation` during the drain stamps `StartTime = T_N`), `SampleFrame()` after dispatch, and considers begin-during-callback self-sampling sufficient. S6 never calls `BeginFrame`, requires `Tick(in FrameTime)` plus a `TickNewlyStarted` method S5 doesn't have, and computes its own `FrameTime`. **Resolution:** S5 implements S6's `IAnimationFrameDriver`; `BeginFrame` is folded into S6 Phase 0 (one line: `scheduler.BeginFrame()` first statement of the frame); `TickNewlyStarted` is either declared satisfied by S5's synchronous-first-sample-at-Begin (S5 adds the method as a documented no-op) or implemented for storyboards ignited by the post-tick styling flush. Pin one of the two clock carriers (frozen `FrameClock` vs passed `FrameTime`).

**9. `AnimationScheduler.Shutdown()` and `CloseAllAsync()` are missing from S6's canonical teardown.** S5 §3.10/§4 requires S6 call `Shutdown()` during session teardown *before* terminal-mode restore (plus one final base-value frame); S4 requires shutdown invoke `CloseAllAsync()`. S6 §3.6's teardown sequence (steps 0–9) contains neither. **Resolution:** insert into S6's teardown between step 0 and step 1: `windowManager.CloseAllAsync()` (dialogs complete null) → `animationScheduler.Shutdown()` → optional final restore frame → then pump cancel/renderer close as written.

**10. `UpdateHover()` has no caller.** S3 §2.5/§4 requires S6 call `dispatcher.UpdateHover()` once per rendered frame, after layout **and** composite parameters are final — it is the named executor for hover-under-scroll/animation and detach-deferred hover work. S6's phase list never calls it. **Resolution:** add to S6 Phase 6 (after `RenderFrame`/composite, before flush) with the S3 wording.

**11. Capability-change fan-out is incomplete in S6.** S3 requires `dispatcher.OnCapabilitiesChanged(caps)` + `accessKeys.OnCapabilitiesChanged(caps)` at startup and after every renegotiate; S7 requires `Application.OnCapabilitiesChanged(caps)` marshaled to the UI thread at the same points. S6's startup/renegotiate sequences call only `styling.OnCapabilitiesChanged` and raise the `CapabilitiesChanged` event. **Resolution:** S6 §3.5 enumerates all four calls explicitly (or pins that S3/S7 subscribe `CapabilitiesChanged` — but then S3/S7 REQUIRES wording must change; pick one mechanism).

**12. S4's frame-ordering guarantee vs S6's phases.** S4 requires "input drain (incl. WM deferred-topology drain) → layout → `OnLayoutCompleted()` → per-surface raster (z order) → `CompositeFrame` → renderer". S6's loop shows none of these as named steps (they're presumably inside `IRenderSystem.RenderFrame`), and the deferred-topology drain "at the next frame's input-drain boundary" has no S6 hook. **Resolution:** S6 §3.3 normatively decomposes Phase 5/6: Phase 1 ends with `windowSystem.DrainDeferredTopology()`; Phase 5 ends with `OnLayoutCompleted()`; Phase 6's `RenderFrame` is defined as raster-then-`CompositeFrame`. (This is also where item 10's `UpdateHover` slots in.)

**13. Layout-pass convergence policy is double-owned.** S1's `LayoutManager.RunLayoutPass(Size rootConstraint)` runs internally to a 16-pass fixpoint with one `LayoutUpdated` retry, per window. S6's `ILayoutSystem` is a global parameterless `RunLayoutPass()` called in an *external* 8-pass loop with `AbandonPendingLayout()` — an API S1 doesn't have — yielding a 16×8 worst case and two competing convergence diagnostics. **Resolution:** one cap, one owner: S1's `LayoutManager` keeps the internal fixpoint; S6's loop calls it **once** per frame per window and only consults `HasPendingWork` for the Phase-7 guard; `AbandonPendingLayout` is added to S1 (the give-up semantics S6 needs) or dropped in favor of S1's slip-to-next-tick behavior.

**14. Click-synthesis pipeline contradiction — S6 default vs S3 contract.** S3 §4 mandates the pipeline be `WithClickSynthesis(new MouseClickOptions { ClickCount = ClickCountTarget.ButtonDown, SynthesizeClickEvents = false })` and treats `MouseEventKind.Click` as a contract violation (defensive no-op). S6's builder documents "default: SynthesizeClickEvents=**true**" and its §2.4 example sets it true. **Resolution:** S6's default flips to S3's contract values; the example is fixed; `WithClickOptions` documents that enabling `SynthesizeClickEvents` violates the S3 router contract (or S6 forbids it).

**15. Dispatch result shape: handled-ness is unexpressible.** S6 requires `bool IInputDispatchTarget.Dispatch(InputEvent)` returning *handled* (gates `ApplyDefaultGestures`, e.g. Ctrl+C exit); S3 provides `ProcessEvent → InputDispatchResult { Dispatched, NotUiInput }` where `Dispatched` includes dropped/unhandled events. **Resolution:** S3's result gains the third state (`DispatchedHandled / DispatchedUnhandled / NotUiInput`) or returns `(InputDispatchResult, bool Handled)`; S6's Ctrl+C gesture keys on unhandled.

## C. Input / focus / access keys

**16. Terminal focus-out vs `LostFocus` — S2 and S3 directly contradict.** S2 §4 pins: "a terminal-level `FocusEvent { HasFocus: false }` MUST produce LostFocus on the physically focused element" (flushes `UpdateSourceTrigger.LostFocus` edits; recorded divergence §6.8). S3 §3.1 pins the opposite: keyboard focus is **retained** on terminal focus-out; no LostFocus is raised; only `TerminalFocusChanged` fires. Also shape drift: S2 wants `event Action<UIElement>? LostFocus`; S3 provides the routed `LostFocusEvent(FocusChangedEventArgs)`. **Resolution:** keep S3's no-focus-move model (it's load-bearing for refocus-restores-state), and give S2 a dedicated flush trigger: S3 raises a non-focus-moving "edit-commit" notification on terminal focus-out (or S2 subscribes `InputDispatcher.TerminalFocusChanged`), and S2's REQUIRES is rewritten to consume the routed event + that notification instead of a CLR `Action<UIElement>`.

**17. The `AccessText` model itself is forked — S3 vs S8 (DECISIONS-shared vocabulary).** Type kind (`sealed record` class in `Cursorial.UI.Input` vs `readonly record struct` in `Cursorial.UI`); conversion operator (implicit vs explicit — S8's critique P0-1 made it explicit *because parsing is lossy*); case normalization (`ToUpperInvariant` vs `ToLowerInvariant` simple-fold); S3 has `Literal()`, S8 has the BMP-letter/digit rejection rule. **Resolution:** one type — adopt S8's shape (struct, explicit operator, BMP rule, case-folded matching) in `Cursorial.UI`; S3's §2.8 is rewritten to reference it; add S3's `Literal` factory.

**18. Access-key *production* rules conflict — S3 forbids what S8 mandates.** S3 §3.7 (critique #12, accepted): "object-typed content properties are NOT folded by the loader; string content acquires its AccessText at presentation time via `ContentPresenter.RecognizesAccessKey`". S8 (critique P0-1, accepted): parse-time folding **is** performed for object-typed slots flagged `ParsesAccessKeyLiterals` (`ButtonBase.Content`, `MenuItem.Header`, `TabItem.Header`, `Label.Content`) plus runtime `GetAccessText()` parsing under the same flag — explicitly so `button.Content = "_Save"` works code-first. Two FINAL specs pin opposite answers to the same fork. **Resolution:** S8's three-producer model wins (it covers code-first and bound strings; the metadata flag is the single source of truth); S3 §3.7's folding paragraph is rewritten, and the Fork A `ParsesAccessKeyLiterals` flag goes on the engine ledger (item 44).

**19. Access-key *registration* ownership conflicts.** S3: the `ContentPresenter` registers/unregisters "on behalf of its nearest `IAccessKeyTarget` templated parent; controls carry NO registration code" — via `AccessKeyManager.Register(char, UIElement)` flat registry + `PushScope/PopScope`. S8: controls call `GetAccessText()` and register on attach/content-change/detach — via an `IAccessKeyScope { IDisposable Register(char, IAccessKeyTarget) }` interface S3 doesn't provide. **Resolution:** control-side registration (S8) against S3's *actual* manager API (flat registry, activation-time scoping — keep it; it solved the ordering/reparent problems): S8's `IAccessKeyScope` REQUIRES is rewritten to `AccessKeyManager.Register/Unregister`, and S3's "controls carry no registration code" sentence plus presenter-side registration are deleted. The presenter keeps only rendering.

**20. Access-key *cue rendering* mechanism forked.** S3: `AccessKeyManager.ShowUnderlineProperty` (attached, default false), flipped by the theme rule `:access-keys ContentPresenter { ShowUnderline: true }`; the ContentPresenter renders the underline. S8: `AccessKeyManager.ShowAccessKeysProperty` — an *inherited* attached bool S3 sets directly at the window root; a dedicated `AccessTextPresenter` leaf renders it (`AffectsRender`). **Resolution:** keep S3's pseudo-class-driven route (themeable, no new inheritance fan-out) but retarget it at S8's renderer: pin one property name (`ShowUnderline`), have `ContentPresenter`/controls realize `AccessTextPresenter` for AccessText content, and the theme rule become `:access-keys AccessTextPresenter { ShowUnderline: true }`. S8's "inherited property set by S3 at window root" wording is deleted.

**21. Access-key gate formula appears in three non-identical forms.** S3 §3.7: `(DistinguishesKeyUpDown && ReportsRepeats) || Win32InputMode`. S6 §2.1 and S8 §3.8: `DistinguishesKeyUpDown && (ReportsRepeats || Win32InputMode)`. Both cite "input.md §7 verbatim". They differ whenever Win32InputMode holds without `DistinguishesKeyUpDown`. **Resolution:** pin one formula from the input map (recommend S3's `||`-of-conjuncts — Win32 input mode is sufficient on its own) and correct the other two; all three keep the undecorated-capabilities sourcing rule (which the three specs *do* agree on).

**22. `AccessKeyEventArgs` / `IAccessKeyTarget` declared by both S3 and S8.** S3: class args (Key, IsMultiMatch, Target), `IAccessKeyTarget { IsAccessKeyEligible; OnAccessKey(AccessKeyEventArgs) }`. S8: `OnAccessKey(in AccessKeyEventArgs)` (struct-shaped) and lists the args type as "S8-owned". Also S8's invocation defaults never mention `IsMultiMatch` focus-only cycling, which S3's manager relies on. **Resolution:** S3 owns both types (it owns invocation); S8's signatures and per-control defaults are amended to honor `IsMultiMatch` (multi-match ⇒ focus only, never invoke).

**23. `Label` targeting needs an API S3 doesn't provide.** S8 requires `FocusNavigator.Next(from)`; S3 only has `MoveFocus(direction)` *from the focused element*. **Resolution:** S3 adds `FocusManager.FindNext(UIElement from)` (pure query over the existing tab-order collection — trivial) and S8's REQUIRES cites it.

**24. `TabNavigation = Once` is required by S8 but explicitly deferred by S3.** S8 ListBox pins `TabNavigation = Once` on items hosts; S3 ships `{Continue, Cycle, None}` and lists `Once/Local` as deferred. **Resolution:** S3 promotes `Once` into v1 (it now has a named consumer), or S8's ListBox spec is rewritten to emulate it (`None` + container `GotFocus` redirection) — recommend the former.

**25. `RegisterWindowKey` doesn't exist.** S8 requires `RegisterWindowKey(Key, mods, owner, priority)` for `IsDefault`/`IsCancel` and the TabControl chords; S3 deliberately routed this through window-root `InputBindings` + the unhandled tail and recorded default/cancel as "an S8 deliverable on InputBindings". **Resolution:** drop `RegisterWindowKey`; S8's buttons install/remove `KeyBinding`s on their window root on attach/detach (focused-element-wins falls out of bubble order). If priority between multiple defaults is needed, S3's `InputBindingCollection` gains ordering semantics — pin it there.

**26. ToolTip's "router-level hit-chain observation hook" is unprovided.** S8 names it a S3 REQUIRES; S3 defers tooltips entirely and provides no such hook. **Resolution:** S3 adds a service-grade event on `InputDispatcher` raised in hover-diff phase 2 (e.g. `HoverChanged(removedChain, addedChain)` over the pooled snapshots — nearly free, the snapshots already exist), and removes "tooltips deferred for lack of a timer" once item 28 lands.

**27. `OnPaste` doesn't exist.** S8 requires `OnPaste { Text }` routed to the focused element; S3 routes `PasteEvent` as `TextInput { FromPaste = true }`. **Resolution:** S8's TextBox consumes `OnTextInput` + `FromPaste` (newline-flattening logic keys on the flag); the `OnPaste` line is deleted from S8 §4.

## D. Ownership gaps (no provider exists)

**28. `IUITimer` has no owner.** S8 requires it from S1 (RepeatButton, ToolTipService, menu hover-open); S1 has no timer surface; S3 explicitly holds no timers; S5 owns `FrameClock`; S6 owns the loop. **Resolution:** assign to S5 (frame-aligned timers sampled in the scheduler's frame pass, sharing `FrameClock`/fake-time testability) — add `UITimer` to S5's surface and re-point S8's REQUIRES; S6's Phase-7 idle guard must include "pending timers" (or timers count as `HasActiveAnimations`).

**29. `ITerminalCaretService` has no owner, and the caret transform spans three subsystems.** S8 requires it from S1 (element-local publish → S1 transforms during frame assembly → back-buffer cursor state after compositing); S1's spec never mentions a caret; S4 owns composite offsets/window positions; S6's `IRenderSystem.RenderFrame` mentions "set buffer cursor state (caret)" in passing. **Resolution:** pin S1 as the service owner (publication registry + element→window transform via `TranslateToWindow`, stale-owner drop on detach); S4 folds the surface offset when assembling; the write lands in `RenderFrame` per S6's line. One paragraph in each of S1/S4/S6 naming their leg.

**30. `IClipboardService` is mis-pointed at S1.** S8 requires it from S1; OSC 52 writes must go through S6's `QueueControlSequence` (S6 explicitly names `ClipboardWriter` as a consumer) and reads through `RegisterDeviceResponseSink`. **Resolution:** S6 provides `IClipboardService` (write via the control-sequence channel; read via a response sink + timeout); S8's REQUIRES re-pointed to S6.

**31. `FindName` has no owner; template-namescope attachment is unwired.** S5 requires `UIElement.FindName(string)` (template-aware) for storyboard targeting; S6's example calls `window.FindName("toast")`; nobody declares it. Separately, S2 pins that the template namescope is "set by ApplyTemplate on the **templated parent**" (`NameScope.TemplateNameScopeProperty`) — S8's seven-step `ApplyTemplate` sequence never sets it, and S8's `DataTemplate.Build` must attach its fresh scope to the item root's document slot (S2's pin) but doesn't say so. **Resolution:** S2 owns `FindName` (defined over `NameScope.FindEnclosing`); S8 §3.1 step 3 adds "set `TemplateNameScopeProperty` on the control from `TemplateInstance.NameScope`" (and clear it in `Detach()`), and `DataTemplate.Build` adds "attach the fresh scope via `NameScope.SetNameScope(root, scope)`".

**32. The Fork A / Fork B / Fork C engines have no owning spec; amendments are scattered across all eight.** Property-system amendments: two-lane `GetEffects`+`GlobalEffects` and the inherited-change virtual (S1), `BindInFrame`/teardown sweep/`SetCurrentValue` observer-args priority/short-name registry query/sentinel ctor (S2), `AnimatedValueHandle.SetValue→bool`/`IsDetached`/idempotent `Dispose`/winning-base observer with inherited routing (S5), `SetCurrentValue`-propagates-two-way (S4), `ParsesAccessKeyLiterals`/`IsSet`/`IPropertyObserver`/`DeferNotifications` (S8), entry-holds-unset (S7). Styling amendments: `IStyleFrameHooks` (S6), edge-action invocation order (S5), `Resume`-before-activate + `Theme.Styles` consumption + `IStyleValueSink` supersession + effective-tier class stamping (S7), Template-layer arming + `PseudoClassSet.Set` sanction + template-`Resources` sealing (S8), root-attach stamping (S6). XAML amendments: converter set (S5/S7), `x:Key`-by-collection-key-type, `IResourceValueBuilder`, `IDeferredValue→IDeferredResourceEntry` rename (S7 Q2), AccessText folding rules (items 17–18). **Resolution:** the design doc gets a consolidated per-engine amendment ledger (one table per fork, each row countersigned), and the three engines get owning implementation specs or are formally assigned (Fork A+B to a ninth workstream; Fork C already has the `Cursorial.UI.Xaml` assembly).

## E. Windowing seams (S4 ↔ S3/S8/S5)

**33. Mouse-gating protocol is specified twice, incompatibly — S3's `IInputSurfaceProvider` vs S4's `IWindowTopology`.** S3 expects a `ReadOnlySpan<InputSurface>` snapshot (record struct: `Bounds`, `IsBlockedByModal`, `IsLightDismiss`) and **drives the light-dismiss/blocked-press sweeps itself** via `NotifyOutsidePress`/`NotifyBlockedPress`; S4 provides `TopLevelSurface` (class) + `FilterMouseEvent` returning `Route/Swallowed` and **performs light dismiss, modal attention, and activation-on-press inside the WM**, with the capture-first bypass + `ObservePointerPosition`. Both claim the same mechanism. S4 also never commits to calling S3's mandatory `OnSurfacesChanged()`, and S4's `IWindowFocusHooks` (`OnWindowBlocked`, `OnSurfaceClosed`, W-DC) has no implementing members in S3. **Resolution:** adopt S4's protocol (it post-dates and resolved capture-first ordering, drag math, and pointer-cell freshness): S3 deletes its provider/sweep and consumes `FilterMouseEvent`; S3 implements `IWindowFocusHooks` (mapping W-DC onto its existing deactivation clears) ; S4 adds the normative "call `dispatcher.OnSurfacesChanged()` on every show/close/modal/z change" line. Hover/enter-leave and intra-surface routing stay S3's.

**34. `ScreenPosition` on routed mouse args.** S4 requires routed mouse args carry both surface-local `Position` and screen `ScreenPosition` (drag math is screen-anchored, normative); S3's `MouseEventArgs` exposes neither name (only `SurfacePosition` + `GetPosition`). **Resolution:** S3 adds `ScreenPosition` (the wrapped device event's terminal position — already retained) to `MouseEventArgs`.

**35. Cross-tree bubbling for popups has no implementer.** S4's `CloseOnEscape` and the whole S8 menu contract are "load-bearing" on routed events bubbling from a popup child's visual root across the logical link to the `Popup` element — S4 files this as an *element-subsystem* REQUIRES, but route building is S3's, and S3's route is a visual-parent walk that stops at the surface root. **Resolution:** S3's route builder is amended: at a surface root with `LogicalParent != null`, continue the route via the logical parent (popup root → `Popup` → host chain). Add the test S4 implies (Esc inside a menu closes the popup, not the window).

**36. Window chrome: PART-name contract (S8) vs role-attached contract (S4).** S8 freezes `PART_TitleBar/PART_Title/PART_CloseButton/PART_ContentHost` at C0 and requires "S4's window Move/Resize/Close *commands*"; S4 §2.2 designs `WindowChrome.HitTestRoleProperty` explicitly as "template-flexible, **no PART_ names**" with the Window interpreting bubbling events per role — and provides no command objects. S8 also claims "S4 ships a primitive chrome painter from its phase 0", which S4's spec never mentions. **Resolution:** S4's role model wins for *behavior* (drag/resize/close/maximize via `HitTestRole` — it's fully specced incl. screen-anchored drag math and gesture over-allocation); S8's default chrome template sets `HitTestRole` on its named parts (PART names remain S8-internal for `GetTemplatePart`, not a cross-subsystem contract); the "window commands" REQUIRES is deleted; the interim-chrome schedule line is moved into S4 (it must ship *some* default template before C4 — pin whose placeholder it is).

**37. Popup contract shape: S8's `IPopupHost`/`IPopupHandle` vs S4's `Popup` element.** Different placement vocabularies (`PopupPlacement{Anchor,Edge,Offset,FlipToFit}` vs `PlacementMode` + `PlacementTarget/Rect` + offsets), different option carriers (`PopupOptions{LightDismiss,HitTestTransparent,TakesFocus}` vs `StaysOpen`/child `IsHitTestVisible`/focus-scope behavior). And S8's explicitly REQUESTED mitigation — a single reusable popup layer per menu session (`IPopupHandle.Move`/content-swap) to avoid two full-target recomposites per top-level menu switch — is absent from S4 (not even in its deferred list). **Resolution:** S8 consumes S4's `Popup` element directly (ContextMenu/ToolTip/submenus wrap one); `IPopupHost` is deleted or demoted to a thin S8-internal adapter. S4 must give an explicit answer to the menu-session request: either add content-swap-without-close on an open `Popup` (surface + scene retained ⇒ no layer-count change) or formally reject it with the cost documented; recommend adding — it is the difference between menus feeling cheap and forcing two full recomposites per hover-switch.

**38. Routed-event storyboard trigger (S4 → S5) is unprovided.** S4 requires "an `EventTrigger`-equivalent attaching `BeginStoryboard` to a routed event" for `ModalAttentionEvent` theme flashes; S5's surface is style-edge actions only and its deferred list doesn't record the gap. **Resolution:** record as an S5 deferral (S4's stated code-behind fallback is the v1 answer), or give `ModalAttention` a transient pseudo-class S3/S4 pulse so the existing edge-action path covers it. Pick one and write it down in both specs.

## F. Binding / lifecycle (S2 ↔ S1/S7/S8)

**39. Logical-tree attach events + the teardown sweep have no provider, and S1's no-leak claim is false under S2.** S2 requires `AttachedToLogicalTree/DetachedFromLogicalTree` events and pins: on permanent detach the "tree/window fork" calls `ValueStore.TearDown()` then `BindingOperations.TearDown(element)` per element, bottom-up. S1 provides only visual-attach virtuals, its detach walk never calls either sweep, and S1 §3.1 asserts "a subtree dropped without detach leaks nothing the GC can't reclaim" — directly contradicted by S2's strong INPC subscriptions to long-lived viewmodels. S4's close path ("detach retracts styles/bindings") assumes the sweep exists. **Resolution:** S1 adds logical attach/detach notifications; defines *permanent detach* (window close via S4, plus an explicit teardown API for app-discarded subtrees) and calls the two-sweep sequence there; corrects the no-leak paragraph to cite the sweep contract.

**40. Detach semantics for `When` watchers: pause (S2) vs dispose (S7/S8).** S2 pins `IBindingWatch.Pause()` as the element-detach parking mechanism ("watchers stay live while armed — Fork B pin"); S7 §3.8 says "styling disposes frame subscriptions as frames disarm" on detach; S8 §3.6 step 2 says subtree detach "disposes `When` condition watchers, and retracts armed style frames". If detach retracts frames (S1's detach walk = Fork B batch retraction), the armed lifetime *ends* and Pause-parking is dead code; if watchers stay armed across detach, S8's retraction list is wrong. **Resolution:** Fork B arbitration required — pin one model. Recommend: detach **retracts and disposes** (matches S1's bottom-up batch retraction, S7, S8, and the reattach-rebuilds-state stance); S2's `Pause/Resume` is then re-scoped to the styling engine's *deactivation* edges only (which is what S7's `ResourceSubscription.Pause` already models), and S2's §2.3/§3.9 wording is amended.

**41. Effective-IsEnabled pipeline: owner and method-name drift, and the property is missing from S1.** S8: `IsEnabled` styled property on UIElement + `IsEnabledCore` + `UpdateIsEnabledCore()`, "computed by S1's inheritance plumbing". S3: `IsEnabledCore` + `InvalidateIsEnabledCore()`, pipeline owned by "the property system" (styling contract C5). S1: declares neither `IsEnabled` nor any effective-enabled machinery. **Resolution:** S1 declares `IsEnabledProperty` and owns the effective-enabled computation on its inheritance wiring (pushing `InteractionState.Disabled`); one method name — `InvalidateIsEnabledCore()` (S3's, already in its public sketch); S8's text renamed to match.

**42. `Window.Content` vs `ContentControl.Content` identity.** S4 registers `Window.ContentProperty` fresh on `Window : Control`; S8's chrome `PART_ContentHost` relies on `ContentPresenter` auto-aliasing, which keys on `TemplatedParent.Content`/`ContentTemplate` being *the `ContentControl` properties*. A separately-registered `Window.ContentProperty` is a different `UIProperty` identity and the alias never engages. **Resolution:** `Window` derives from `ContentControl` or `AddOwner`s `ContentControl.ContentProperty` (S4 already uses the AddOwner pattern for Width/Height — extend it).

**43. Generated item containers: logical-vs-visual parent plumbing.** S1's `UIElementCollection` (used by `Panel.Children`) sets **visual AND logical** parent; S8 requires containers be logical children of the *ItemsControl* while being visual children of the items panel. As specified, the panel adoption would steal logical parentage. **Resolution:** S1 adds a visual-only adoption path (`Panel.Children` flag or internal `AddVisualChildOnly`) used by `ItemsPresenter`; pinned in S1's §2.3 and cited from S8 §3.6.

## G. Resources / theming (S7 ↔ S6/S8)

**44. Two application objects: S6's `UIApplication` vs S7's `Application`.** Different types, different members (`Dispatcher/Capabilities/Styles/ThemeVariant/RunAsync` vs `Theme/RequestedThemeBase/RequestedColorTier/ActualThemeVariant/ResourcesChanged/OnCapabilitiesChanged`), both claiming `Current`; S4 references `Application.Current.WindowManager` (a third member set); DECISIONS pins the name `UIApplication`. Also a behavioral split: S6 says styling re-stamps caps classes from *negotiated* capabilities; S7 pins color-tier classes stamped from the **effective** tier (`ActualThemeVariant.Tier`, honoring `RequestedColorTier`) off `ActualThemeVariantChanged`. **Resolution:** one type, `UIApplication`, merging both surfaces (S6 owns the host/loop half; S7's theme surface becomes members of the same class); S6's `ThemeVariant` property is replaced by S7's `ActualThemeVariant`; S6's renegotiate sequence calls `OnCapabilitiesChanged` (item 11) and the capability-class stamping rule is corrected to S7's effective-tier pin; S4's `WindowManager` ambient joins the merged surface.

**45. Default-theme ownership and key vocabulary are doubled — S7 vs S8.** S7 owns `CursorialTheme.BuiltIn` (code-first, `ThemeKeys` = `"Theme.*"` strings, tier-key layout rules, control themes at `ControlTheme(0)`); S8 §1 claims "S8 owns: the default theme (`Themes/Default`)" with a different key vocabulary (`AccentBrush`, `SelectionBrush`, `WindowBackground`, `MenuBackground`, `CheckBoxGlyphs`, …) and its SaveDialog example uses `{DynamicResource AccentBrush}`. **Resolution:** split by layer: S7 owns the theme *infrastructure* (BuiltIn dictionary, variant layout, `ThemeKeys` naming convention, palette spine); S8 *authors the content* (per-control templates/styles + control-specific keys) into S7's structure under `Theme.*` names. S8's key list and example are renamed (`Theme.AccentBrush` etc.), and S8's §1 ownership line is rewritten to "the default theme's control templates/styles, hosted in S7's `CursorialTheme.BuiltIn`".

**46. Glyph-tier resources don't fit the variant axes.** S8 repeatedly keys glyph resources on a "`caps-unicode` tier" of theme dictionaries (`( ) (*)` → `(•)`/`☐☑`, `▲▼` vs `^v`, `Pens.Ascii`); S7's `ThemeVariantKey` axes are exactly `ThemeBase × ColorDepth` — there is no Unicode axis, and S7 §6.3 deliberately uses the color tier as the proxy for glyph capability. **Resolution:** pin the mechanism: glyph resources live at color-tier keys (S7's proxy stance) **plus** an explicit escape for the mismatch cases via capability-class-selected styles (`caps-ascii Selector` setting the glyph resource reference). S8's "`caps-unicode` tier" wording is amended to whichever is chosen.

**47. TextBlock markup staleness contract contradicts S7's pulse model.** S8 §3.9 has TextBlock "subscribe to `ResourceDictionary.Changed`" and a format cache keyed `(text, width, caps)`; S7 pins that sealed dictionaries **never** pulse, variant flips fire only `Application.ResourcesChanged`, and the *named S8 contract* is to include `(ResourceServices.GetResourceVersion(this), ActualThemeVariant)` in `FormattedText` cache keys. As written, S8's TextBlock goes stale on every theme-variant flip. **Resolution:** S8 adopts S7's contract verbatim (cache key gains the version+variant pair; the dictionary subscription is deleted).

**48. S7's template-resource hop needs members S8's template types don't have.** S7's chain walk reads `tp.TemplateInstance?.Template` and `Template.Resources` (sealed at template seal); S8's `ControlTemplate` has `Styles` but no `Resources`, and the pinned `TemplateInstance` shape (`Root/NameScope/Detach`) has no `Template` property. **Resolution:** S8 adds `ControlTemplate.Resources` (sealed in `Seal()`, per S7's Fork B line) and `TemplateInstance.Template`; or S7 drops the template-resource hop for v1 — recommend adding (S7's walk and the "template-shipped values" story depend on it).

**49. `StyleKey` (S8) vs `ControlThemeKey` (S7) — same concept, two names/types.** S8: `protected virtual Type StyleKey => GetType()`; S7: `protected virtual object ControlThemeKey => GetType()` with exact-key/no-base-probing semantics and the `Control.ThemeProperty` override. Also S7 describes the theme's template setter as "holding an `ITemplateContent`" while S8's `TemplateProperty` is typed `ControlTemplate?`. **Resolution:** one member — adopt S7's `ControlThemeKey : object` (theme keys are dictionary keys) with S7's exact-key semantics; S8's `StyleKey` is renamed; S7's wording corrected to "a setter holding a `ControlTemplate` (whose `Content` is the `ITemplateContent`)".

**50. Resource pulses don't reach popup surfaces.** S7's subscription registries are per *visual root*; popup children are roots of separate S4 surfaces whose resource chain runs logically into the host window. A window-scoped dictionary mutation routes to the *window's* registry only — DynamicResource consumers inside an open popup are never swept. **Resolution:** S7 pins cross-surface routing: nodes register under the registry of the root their *logical* chain tops out at (the host window), or host-scope pulses fan to owned popup-surface registries via an S4-provided surface→host map. Pick one; add the menu-open-during-theme-flip regression test.

## H. Animation details (S5 ↔ S1)

**51. Storyboard target property names don't exist in S1.** S5's table and examples target `OffsetColumn`/`OffsetRow` and a `CompositeClip (Rect?)` property; S1 declares `RenderOffsetColumn`/`RenderOffsetRow` and **no** clip property (`ClipToBounds` is a bool). **Resolution:** unify on S1's `RenderOffset*` names (S5 text/example fixed); for the reveal/wipe lane either S1 adds a styled `CompositeClip` (`AffectsComposite`, boundary-promoting — cheap given the boundary walk already publishes clips) or S5 deletes the row as deferred. Decide explicitly.

**52. `Thickness` vs `Margins`: S5's rationale contradicts S1's pinned policy.** S5 §2.6/§6.8 asserts "Thickness is signed — that is WHY S1 mints it; negative margins are legitimate"; S1 §2.2 pins "negative margins are unsupported in v1, coerced to 0 (signed-margin vocabulary deferred)". **Resolution:** resolve S5's Open Q1 against S1's actual stance: v1 reuses `Margins` (unsigned); `ThicknessTrack/ThicknessTransition/ThicknessInterpolator` are cut or re-typed to `Margins` with the clamping family; the no-clamp/signed rationale moves to the deferral record alongside S1's signed-margin deferral.

## I. Controls behavior conflicts (S8 ↔ S3)

**53. ButtonBase Space activation violates S3's capability rule.** S8: "Space down → `IsPressed = true`; Space **up** over → click". S3 (normative, in its own ButtonBase consumer example): "Activate on Down, not Up: KeyUp exists only on Kitty/Win32 terminals — never gate core activation on it." On legacy terminals S8's Space never clicks. **Resolution:** S8 amends: Space clicks on **Down** (with `IsRepeat` guard); the pressed-latch visual is a capability-gated nicety on terminals that report Up (and is already cleared on `OnLostFocus`).

**54. Who writes `:pressed`, and through which seam.** S3 routes `Pressed` through `SetInteractionState(InteractionState.Pressed, …)`, which fans into the dispatcher's **pressed-holder set** — the mechanism behind C8 (terminal focus-out clears Pressed window-wide) and W-DC (deactivation clearing). S8 makes `IsPressed` a `DirectProperty` written to the pseudo-class via raw `PseudoClassSet.Set`. If S8's route bypasses `SetInteractionState`, both clearing guarantees silently break. **Resolution:** `Pressed` stays an `InteractionState` flag set via `SetInteractionState` (S3's seam); S8's `IsPressed` DirectProperty mirrors it for binding/`When` use; `PseudoClassSet.Set` remains sanctioned only for the genuinely control-semantic classes that have no InteractionState bit (`:open`, `:highlighted`). S8 §2.4/§5-R8 amended.

**55. `ButtonBase.Click` event shape forked.** S3's example: routed `ClickEvent` (`RoutedEvent<RoutedEventArgs>`, Bubble, pooled `RentEvent`); S8: plain CLR `event EventHandler<ClickEventArgs>` with an S8-owned args class. **Resolution:** routed event + CLR sugar (WPF kinship, lets window-level handlers observe clicks); `ClickEventArgs : RoutedEventArgs`. S8 owns the type; S3's example updated to match.

**56. Menu-mode entry hook mis-pointed.** S8 lists `IMainMenu` ("window-level Alt/F10 target") as PROVIDES **to S4**; the actual consumer is S3's `AccessKeyManager.EnterMenuMode` (Alt tap), and F10 appears nowhere in S3. **Resolution:** `IMainMenu` registration points at S3 (the `EnterMenuMode` subscriber); S3 adds F10 to the menu-mode entry gesture set (or S8 drops F10); S8's PROVIDES line re-pointed.

## J. Hygiene / vocabulary
