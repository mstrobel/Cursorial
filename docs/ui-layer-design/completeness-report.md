## 1. Requirement-by-requirement coverage

**R1 — Rich styling and templating: COVERED, with one structural caveat.**
Selector subset + `When`, one Style slot, `StyleSortKey` layers, `PseudoClassMapping`, template barrier: Fork B canonical proposal as amended by DECISIONS. Templated controls, `ControlTemplate`/`DataTemplate`, part contract (`[TemplatePart]`, apply-time validation), measure-time expansion, re-templating retraction (`OnTemplateDetaching` → `TemplateInstance.Detach()`), `ContentPresenter` auto-aliasing, lookup chain: S8 §2–3. Control themes (`Type`-keyed, `ControlTheme(0)` layer, `Control.Theme`/`ControlThemeKey`), default theme with tiered variants: S7 §3.7. Style inheritance via `BasedOn` exists in the canonical proposal (flattened at `Seal`, cycle-checked) — not a gap. *Caveat:* there is **no final subsystem spec for the styling engine itself** (nor property system, nor XAML) — their final shape is "canonical proposal + amendments scattered across eight specs." See §3, "amendment sprawl."

**R2 — Powerful data binding: COVERED, with two seam defects.**
S2 is comprehensive: paths/indexers/attached segments, five modes + `BindsTwoWayByDefault` + read-only degradation, three triggers, Source/ElementName/RelativeSource (Self/TemplatedParent/FindAncestor) on both reflection and compiled lanes, converters/StringFormat/FallbackValue/TargetNullValue with a fully specified reverse lane, frame-hosted entries, `Watch` for `When`, release-build `Explain`. TextBox per-change push pinned jointly (S8 §3.9, S2 §6.3). Defects: (a) **S2 §4 pins "terminal `FocusEvent{HasFocus:false}` MUST produce LostFocus on the focused element" (to flush LostFocus-triggered edits on Alt-Tab); S3 §3.1 pins the opposite — keyboard focus is retained on terminal focus-out and no LostFocus is raised** (only `TerminalFocusChanged` for S4). The `UpdateSourceTrigger.LostFocus` flush-on-focus-out divergence S2 records (§6.8) is currently unimplementable against S3. (b) **Collection views (sort/filter/group/current-item) fell into a pointer cycle**: S2 defers them to "the items-control subsystem"; S8 never mentions them (its `ItemsSourceView` is index normalization only). No spec owns even a recorded deferral with reasons.

**R3 — Resource/style inheritance: COVERED.**
Positional inheritance (chain walk, nearer shadows farther, templated-parent hop pinned jointly S7 §3.3 / S8 §3.4), thematic inheritance (variant probe, minimum-capability tier descent, the truth table and lint), palette indirection (`ThemeKeys` + DynamicResource spine — one key override re-skins the tree): S7. Value inheritance: Fork A `Inherits` (DataContext, `TextElement.Foreground/TextAttributes` in S8 §2.1). Style inheritance: `BasedOn` + scoped `Styles` (proposal §5). Child-window-to-owner chaining: decided no, recorded (S7 §8 Q1).

**R4 — Logical and physical focus (WPF-like): COVERED, with two un-countersigned S8 dependencies.**
Physical focus, `IsFocusScope` scopes with memory, `ActiveRoot`, restoration on window activation and **popup close (the menu round-trip: S4 `OnSurfaceClosed` → S3 restores the host's remembered logical focus)**, detach hygiene with eager scope-memory clearing, Tab (Continue/Cycle/None, window roots trap by default — modal trapping free), directional navigation, `:focus/:focus-within/:focus-visible`: S3 §2.7/§3.5–3.6. Gaps: (a) S8 requires **`TabNavigation = Once`** for items hosts (ListBox) — S3 §7 *explicitly defers* `Once/Local` ("ship the three modes"). (b) S8's `Label` requires **`FocusNavigator.Next(from)`** (next focusable after an arbitrary element); S3 only exposes `MoveFocus(direction)` from the *currently focused* element. Both are small APIs, but neither is in S3's spec.

**R5 — Modal and modeless child windows: COVERED, with API-shape drift.**
Modal input scoping (enabled set = topmost modal + transitively-owned closure; blocked surfaces occlude all pointer events; keys structurally cannot reach blocked windows because activation redirects to the gate): S4 §3.3 + S3 §3.4. Nested modals (stack, out-of-order pops, gate recompute): S4 §3.3/§3.5. Dialog results (`ShowDialogAsync<T>`, `DialogResult`, UI-context cancellation, pre-canceled tokens): S4 §3.3; async-only modal pinned normatively by S6 (no nested pumps). Owner cascades, universal activation handoff, `ModalAttention`, `.obscured` dimming with Ansi16 fallback recipe: S4. Partial-coverage items: (a) **`IsDefault`/`IsCancel`**: S3 defers it to S8 "on window-root `InputBindings` + the unhandled tail"; S8 instead requires a `RegisterWindowKey(key, mods, owner, priority)` API S3 never defines — mechanism mismatch. (b) **Chrome contract conflict**: S4 §2.2 is explicitly "template-flexible, **no PART_ names**" (`WindowChrome.HitTestRole`); S8 freezes `PART_TitleBar/PART_Title/PART_CloseButton/PART_ContentHost` at C0 and asks S4 for window Move/Resize/Close *commands*. Reconcilable (roles + parts can coexist) but the two FINAL specs contradict as written. (c) **Popup API shape**: S8 consumes `IPopupHost/IPopupHandle.Move` + `PopupOptions`; S4 ships a `Popup` element with equivalent guarantees but no service interface and no `Move`/content-swap; S8's requested **single reusable popup layer per menu session** (to avoid two full recomposites per top-level menu switch) appears nowhere in S4.

**R6 — Access keys (the full matrix): COVERED end-to-end, but the S3↔S8 seam has real drift.**
- *Capability gate:* pinned identically three times — S3 §3.7 (`DistinguishesKeyUpDown && ReportsRepeats || Win32InputMode`), S6 (`SupportsAltKeyTracking` from the **undecorated** snapshot, KeyReleaseSynthesizer-spoof-proof), S8 §3.8 (same sourcing rule, extended to the Ctrl+Tab gate). Consistent. Re-evaluated on `RenegotiateAsync` (all three).
- *Alt-toggle terminals:* S3's cue state machine (per-side bracketing, stale-bracket inference, Alt-tap sticky/menu mode, Esc pre-stage consume, chord-flash self-correction for unverified Kitty pushes, synthesized-event exclusion).
- *Permanent-underscore terminals:* `AlwaysVisible` cue stamped on **every surface root** including popup roots (S3 §3.7) — pure styling downstream.
- *Focus-loss clearing:* `FocusEvent{HasFocus:false}` → unconditional clear of side bits/sticky/cue (S3); renegotiation pump-park clear (S3 `OnCapabilitiesChanged`).
- *Menu scoping:* `PushScope/PopScope` with activation-time scope resolution (ordering-proof); S4 calls them on popup open/close; menu-mode unmatched-key swallow; multi-match cycling.
- *XAML folding:* type-driven fold (DECISIONS Fork C) + S8's `ParsesAccessKeyLiterals` metadata flag + runtime `GetAccessText()` — three producers, one `Parse`; data strings (`ListBox` items, `TextBlock.Text`) never mangled.
- *Drift to reconcile:* S3 and S8 define **conflicting shapes of the same pipeline**: S3's `AccessText` is a `sealed record` with an *implicit* string conversion and upper-invariant key; S8's is a `readonly record struct` with an *explicit* conversion (P2-27) and lower-invariant folding. S3 pins "registration lives in the `ContentPresenter`; controls carry no registration code" and "object-typed content properties are NOT folded"; S8 pins control-side registration via `GetAccessText()` and *does* fold flagged object-typed slots. S3's cue property is `ShowUnderlineProperty` flipped per-presenter by a `:access-keys` theme rule; S8's `AccessTextPresenter` reads an inherited `ShowAccessKeysProperty` set at the window root. Every one of these has a working answer in S8 (the later, post-critique spec), but S3's text was never updated — an implementer following S3 will build a different (and per S8's P0-1, *broken for code-first*) pipeline.

**R7 — XAML incl. template plumbing: COVERED via Fork C + scattered seams.**
Runtime loader, type-contract deferral (`ITemplateContent` — S8's `ControlTemplate.Content` consumes it), markup extensions with `IDeferredValue.AttachTo`, namescopes (document/template split with the guarded walk, pinned S2 §2.6 jointly with Fork C), X4 generator (`x:Name` fields, `InitializeComponent`, AccessText fold, `[TemplatePart]` cross-check diagnostics), compiled-binding descriptor contract (S2), converter inventory (S5 §4: `UIProperty`/`Easing`/`Optional<T>`/`RepeatBehavior`; S7 §4: `ThemeVariantKey` x:Key conversion, `IBrush`/`Pen`/`RelativePoint`; S3: `KeyGesture`), `IResourceValueBuilder` media builders (S7 §2.6), deferred resource entries. Same structural caveat as R1: no final XAML subsystem spec; the `IDeferredValue`→`IDeferredResourceEntry` rename (S7 Q2) and the metadata-flag fold (S8) are amendments awaiting Fork C sign-off.

**R8 — Setters + hybrid trigger/selector model: COVERED, one ceded-but-unclaimed corner.**
The model itself: Fork B as decided. Controls feed it: S8's pseudo-class registrations + sanctioned `PseudoClassSet.Set` for DirectProperty state. Data half: S2 `Watch` (self-source + ancestor-source in B0). Animation half: S5's `IStyleEdgeAction`/`BeginStoryboard`/`StopStoryboard` with no-throw runtime policy. Resource half: `ResourceReference` setters riding frames (S7 §3.4). Gap: the styling proposal **explicitly cedes `EventTrigger` to the animation fork**, S4 **requires** a routed-event trigger equivalent (`ModalAttentionEvent` flash), and **S5 never provides one** — only style-edge actions. S4 records a code-behind degradation, but the requirement landed in a zone both sides ceded.

**R9 — Prioritized-source properties with efficient storage: COVERED.**
Fork A as decided (frames, two-slot split, store-owned promotion, `AnimatedValueHandle<T>`, box-interning, oracle matrix first). Consumer discipline is consistent across all eight specs (`SetCurrentValue` for control writes, `DirectProperty` for hot state, effects metadata on every registration, nullity-escalation pattern). Caveat: the **amendment pile** (see §3) is the load on this requirement.

**R10 — Rich animation: COVERED.**
S5 in full: imperative handles, storyboards (targeting/stagger/repeat/fill/seek on the storyboard timeline), transitions (phase-gated, honestly sized seam), reduced-motion, detach stop pass, `Shutdown()`, frame protocol with S6 (`BeginFrame`/`SampleFrame`/`TickNewlyStarted`). Composite lane (`RenderOffset*`, `Opacity`) and the routing table enforce invariant 3. S8 supplies the reference composite-only animation (ProgressBar indeterminate via store-routed `AffectsComposite`). Partial items: S5's animatable **`CompositeClip` (`Rect?`) property does not exist in S1** (S1 has only `ClipToBounds : bool`) — the reveal/wipe row of S5's table has no substrate; **`Thickness` vs `Margins` is unresolved in opposite directions** (S5 Q1 recommends S1 mint signed `Thickness`; S1's final spec keeps `Margins` with negatives coerced to 0); smooth scrolling impossible (direct-property offsets) — recorded honestly in S8.

## 3. Gaps and cross-spec contradictions

### A. Contradictions between FINAL specs (the union is not coherent; these are completeness failures even though each spec is internally complete)

1. **The scene-granularity/layer model — three pinned, mutually exclusive answers.** S1 §3.7: one Scene per *render boundary* (Opacity<1, RenderOffset≠0, ClipToBounds, SCP, explicit hint — many zones/layers per window, sticky promotion, `RenderTree.CollectLayers` handing multiple layers per window to S4). S4 §7: one scene per window surface, "per-window scene stacks deferred — v1 implements exactly 1," with its own `TopLevelSurface.Render`/`ISurfaceRasterizer` path that never calls S1's `RenderTree`. S8 §3.5: one scene per window + `IElementLayer` sub-scenes for exactly {banded scroll viewports, ProgressBar indeterminate, S4 surfaces} — claimed "pinned with S1 (§4 REQUIRES)," but **S1's text contains neither `IElementLayer`/`RequestLayer` nor the band model**: S1's `ScrollContentPresenter` is extent-sized with a 262,144-cell budget + degraded fallback, directly contradicting S8's viewport+2K band with re-anchor (S8's model was built to fix the exact problem S1's fallback documents). One of these must win before T3/W0/C3.
2. **S8's REQUIRES-from-S1 services that no spec provides:** `ITerminalCaretService` (S6's `IRenderSystem` has one parenthetical "set buffer cursor state (caret)"; S1 never mentions carets), `IUITimer` (S3 deliberately has no timers and *defers tooltips for lack of a timer service*; S5's clock is not a timer service), `IClipboardService` (S6's `QueueControlSequence` is a byte channel, not a service with `CanRead/TryGetTextAsync`), `UIElement.RequestLayer(LayerOptions)`, and S3's **router-level hit-chain observation hook** (S8 calls it "a named S3 REQUIRES item"; S3's final spec defers tooltips entirely and contains no such hook). TextBox, RepeatButton, ToolTipService, and menus all gate on these.
3. **Effective-IsEnabled pipeline is orphaned.** S3 §4 pins it on the property system ("the effective-IsEnabled pipeline consults `IsEnabledCore`… owns the `Disabled` flip"); S8 §4 pins it on S1-tree ("computed on the inheritance plumbing"); S1's spec doesn't define `IsEnabled` at all. Everyone requires it; nobody owns it.
4. **`ClipToBounds` means two incompatible things.** S3 §4 requires `ClipsToBounds = true` as the *panel default* (named hit-test-pruning perf contract); S1 defines `ClipToBounds` default *false* and **boundary-promoting** — under S1's model, S3's default would promote every panel to its own scene/layer (layer explosion, the compositor's worst case).
5. **Click-synthesis defaults disagree.** S3 §4: pipeline must use `SynthesizeClickEvents = false` (Click events forbidden; defensive no-op). S6 §2.1: builder default `SynthesizeClickEvents = true` (and the example sets it true). Safe due to S3's defense, but the pinned contracts conflict.
6. **R6 seam drift (S3 vs S8)** — detailed under R6 above: `AccessText` shape, registration ownership, fold policy, cue-property mechanism.
7. **TextBlock markup staleness mechanism**: S7 §2.4 designed `GetResourceVersion` + `ActualThemeVariant` cache keys *specifically for S8*; S8 §3.9 instead subscribes to `ResourceDictionary.Changed` — which per S7 **never fires on sealed dictionaries or variant flips** (the signal is `Application.ResourcesChanged`). As written, S8's TextBlock misses theme-variant flips.
8. **`SceneCompositor` ownership**: S1 §4 assigns it to S6; S4 §8 Q2 claims it for the WM (asking S6 to confirm); S6's `IRenderSystem` is agnostic. Needs one line.
9. Minor: S5 targets `OffsetColumn/OffsetRow` (S1 names them `RenderOffsetColumn/Row`); S1's internal 16-pass layout cap vs S6's external 8-pass cap + `AbandonPendingLayout` (S1 has no abandon API).

### B. Things a WPF/Avalonia veteran would expect — never mentioned (vs. properly deferred)

- **Accessibility/automation** (AutomationPeer-equivalent, screen-reader story): not mentioned in any spec beyond S8's one caret aside. Even "no story in v1, recorded" is absent. Given the caret-as-terminal-cursor design partially motivates itself with assistive tech, this deserves a recorded stance.
- **Alternating-row styling**: `:nth-child` is fenced out by DECISIONS *and* WPF's `AlternationCount/AlternationIndex` never appears — zebra-striped lists, a bread-and-butter TUI pattern, have no mechanism and no recorded deferral.
- **Collection views** (sort/filter/current-item) — the S2↔S8 pointer cycle (see R2). Effectively never owned.
- **`Window.Title` → terminal/tab title (OSC 2)**: S6 built the sanctioned channel and names "window titles" as a consumer, but no spec wires `Window.Title` (or the main window) to it.
- **Grid `SharedSizeGroup`/`IsSharedSizeScope`**: absent without record (minor; form layouts notice).
- **Localization/`x:Uid`**: absent without record (arguably out of scope; one line would close it).
- Properly deferred with reasons (fine, listed for contrast): MultiBinding/PriorityBinding, `INotifyDataErrorInfo` validation (+ reserved `:data-error` seam), `Binding.Delay`, RoutedCommand/CommandManager, drag-and-drop, subtree capture, ComboBox/Slider/TreeView/DataGrid/PasswordBox/multi-line TextBox/undo, virtualization (with corrected cost model), `DataTemplateSelector`, `x:Shared`, smooth scrolling, mouse cursor shapes, tooltips-need-timer (S3 side), minimized/topmost windows, `UpdateSourceTrigger` knob, `SpeedRatio`/`HandoffBehavior.Compose`/additive animations, interface-based implicit templates.

### C. Process gap — amendment sprawl

Fork A/B/C have no final specs; their binding shape is the canonical proposals plus **~25 amendments scattered across the eight specs**, many flagged "needs countersignature" and none aggregated: Fork A (`GlobalEffects` lane, inherited-change virtual, `BindInFrame`, `SetCurrentValue` observer-args priority + two-way write-through, `ParsesAccessKeyLiterals`, `IsSet`, auto-alias observer channel, winning-base observer with `IncludeBaseChanges` — "NOT small", `AnimatedValueHandle.SetValue` bool + `IsDetached`, `FindOwnersByShortName`, sentinel ctor, `ValueStore.TearDown`, effects-parameter on Register); Fork B (`IStyleFrameHooks`, edge-action invocation order, Resume-before-activate, theme `Styles` consumption, template-resource sealing, `IStyleValueSink` sweep *supersession* by S7); Fork C (`IDeferredResourceEntry` rename, x:Key conversion semantics, `IResourceValueBuilder`, metadata-flag folding, `EmergencyRestoreBytes` on Core). A consolidation pass per fork, before implementation starts, is the single highest-leverage hygiene action.

## 4. The five riskiest design bets, each with a cheap de-risking probe

1. **Scene granularity / composition model (finding A1) — the one guaranteed-rework item if unreconciled.** S8's "whole-window-scene re-raster is fine, bounded" claim is the load-bearing simplification; S1's zone machinery is the hedge against it being wrong. *Probe:* `Cursorial.Drawing` already ships — write a benchmark demo (no UI layer needed): raster a realistic 200×60 window scene (boxes, gradients, formatted text, ~300 draw ops) per frame at 60fps plus `FrameRenderer` diff, and a banded-viewport re-anchor, on target hardware. One day; the numbers decide whether S8's model holds, which decides how much of S1 §3.7 to build.
2. **Fork A ValueStore under the amendment pile**, especially the three cross-cutting behaviors two subsystems each gate on: `SetCurrentValue` two-way write-through (S4 W3 gate), the winning-base observer under animation incl. inherited routing (S5 A3 gate, self-labeled "NOT small"), and frame-hosted entry eviction order (S2/Fork B). *Probe:* author the mandated oracle-pinned precedence matrix *now* (before any engine code) including those three rows, plus a throwaway store spike benchmarked at 300 elements × hover-flip churn for the allocation claims.
3. **The Alt/access-key gate on real terminals** — the Kitty push is unverified by design, the chord-flash self-correction is a novel heuristic, and many desktop environments eat Alt before the terminal sees it. *Probe:* an afternoon `accesskeys` command in `Cursorial.Demo` (the repo already has the probe/trace infrastructure) logging Alt Down/Up, FocusEvent, and the gate inputs across kitty, WezTerm, Windows Terminal, xterm, tmux, Alacritty — validates S3 §3.7's truth table against live wires before S3 exists.
4. **Any-event mouse motion budget end-to-end** — hit test per cell crossed, two-phase hover diff, `InteractionState` batch + restyle, pause/resume flag discipline (S7), edge-bounded storyboard ignition (S5), and S8's "re-raster only on hit-chain change" all stack on the same hot path; each spec costs its own slice, nobody has costed the sum. *Probe:* a UITestHost motion-storm benchmark (sweep 200 columns across a ~300-element tree with hover styles + a tooltip), asserting zero steady-state allocation and per-frame time within the 33ms budget; make it a CI gate at C1.
5. **The window/popup topology state machine** — deferred-topology queue, universal activation handoff across close cascades, light-dismiss chains, popup focus restore, and menu layer-count churn (the un-countersigned reusable-popup-layer request) interact combinatorially; this is where async-modal designs historically rot. *Probe:* write S4's scenario matrix as UITestHost scripts *before* W2/W3 (modal opened from a timer mid-drag, out-of-order modal close, cancel-token races, menu→submenu→switch-top-level), asserting `WindowDiagnostics.DumpZOrder` + focus/capture invariants; plus a menu hover-switch stress demo to measure the two-full-recomposite cost and decide the reusable-layer request on evidence.

**Bottom line:** the ten requirements are all substantively covered by the union — none is silently dropped, and the deferral discipline is excellent where it was applied. The completeness failures are concentrated at the seams: one architectural three-way contradiction (scene/layer model), five S8 service dependencies without providers, the S3↔S8 access-key drift, the S2↔S3 LostFocus contradiction, two ownership orphans (effective-IsEnabled, SceneCompositor), and the unconsolidated fork-amendment pile. All are reconcilable on paper; none should survive into phase 0.
